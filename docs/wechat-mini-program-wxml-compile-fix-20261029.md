## 两类证据不能混淆

工具安装包内`getservice.js`在自身`_env`没有合法编译服务环境值时抛出截图错误；
该堆栈不提供具体项目文件/行列。读取厂商代码有助定位报错层，但不能仅凭这个
通用异常认定项目无错，也不授权修改工具安装文件或强制升级/关闭用户GUI。

实际使用同一安装里的官方`wcc.exe`检查桌面模板，发现明确的项目错误：

```text
pages/device/index.wxml:8:4: Bad attr `wx:else`
wx:if not found, then something must be wrong
```

上轮新增“安卓扫码配网”卡片插在真实设备面板的`wx:if`和预览块的`wx:else`之间，
破坏了WXML要求的相邻条件链。旧Node/TS smoke未验证这种模板语法，所以全绿
不能当作官方模板编译通过。配网页自身和app-page模板当时单独编译已通过。

## 最小修复

将预览根块从`wx:else`改成独立的`wx:if="{{!liveMode}}"`。不移动卡片、不更改
布局、绑定/登录、请求、动作、配网参数或权限；仍为：

- 真实设备面板仅真实模式显示。
- 配网入口卡片两模式均显示。
- 原预览内容仅非真实模式显示。

`smoke-debug-entry.cjs`新增同一结构的回归，检查预览有自己的条件及原显示顺序。
不是靠删配网页、隐藏入口、放松核权或改工具配置来避开错误。
