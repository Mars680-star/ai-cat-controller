# 跨进程维护协议 V1：本地源码与宿主验证

> 2026-10-21。仅本地开发；未访问K1、读取私有凭据、部署、重启或调整硬件。
> 协议默认不启用，小程序危险按钮仍禁用。尚未完成全部进程参与和真机验收。

## 解决的实际缺口

单个FastAPI实例的[维护门](device-operation-gate.md)不能约束另一个Python实例、
独立自主播音线程、原生云语音进程或仍然存活的播放器子进程。本阶段增加协作式
Linux文件锁协议，覆盖这些参与者真实工作的生命周期，不用“进程看起来不忙”
或一个marker文件冒充排空证明。

当前实现范围：

| 参与者 | 新增本地源码行为 |
| --- | --- |
| FastAPI正常服务入口 | 完整操作持共享工作锁；HTTP入口捕获跨进程票据；维护先闭准入，再等本机及外部工作锁 |
| 独立/进程内自主线程 | 每轮状态读取、资料决策、HTTP提交、等待和播音共享一个票据；每个可选新效果前重查 |
| 本地播放器 | marker、真实播放、超时清理全跨度共享锁；播放器显式继承工作FD，keeper崩溃也不提前放锁 |
| 固定命令执行器 | 实际普通服务租约中的固定子命令继承工作FD；只继承共享工作锁，不交出独占维护锁 |
| 原生云语音 | 在任何运行文件、声卡或云操作前入门；整个进程持共享锁，关闭时拒绝新输入、音频和工具，实际收尾后退出 |
| 原生电机CLI | 非停止入口在初始化驱动前取得共享锁，覆盖动作和清理；停止仍旁路 |
| 原生唤醒词 | 捕获、识别至本轮语音交接同一窗口票据；真实关流后释放，恢复不重放旧口令 |
| 直接LocalK1Adapter | 完整普通写与必要子任务受保护；自有/借用门正确排空，纯读与安全命令旁路 |

普通查询、停止和打断保留原权限校验，不因维护而排队。多个控制器实例现在可
协调维护排空，**不等于整个产品已支持多worker部署**：网页会话、普通命令仲裁、
单文件对话请求生产者竞争等仍需分别解决。

## 目录与二进制合同

配置项是可选的`AI_CAT_PROCESS_GATE_PATH`。未设置保持原兼容行为；显式空值、
相对路径、控制字符、空组件、`.`、`..`和尾斜线均拒绝。Python的显式Settings同时
决定自主线程与固定命令环境，不被另一条ambient路径暗中覆盖。

协调目录必须是本机Linux文件系统的专用目录，最终目录0700、当前有效用户所有。
逐层`openat(O_DIRECTORY|O_NOFOLLOW)`，拒绝祖先符号链接；协议成员0600、普通文件、
同一有效用户、单硬链接。锁文件还必须为空。当前对象固定目录和两把锁的dev/ino，
后续发现被替换就拒绝，不靠重新创建恢复。

**不能使用`/run/ai-cat`**：原语音unit管理其生命周期，正常退出可能清掉整个目录。
也不能把协调目录纳入格式化、运行文件归档、备份恢复覆盖或日志轮转。建议将来受控
部署采用独立目录，如`/var/lib/ai-cat-process-coordination`，但本轮没有在设备创建它。

固定三个成员：

- `admission.lock`：真实准入闸门，inode永不替换。
- `work.lock`：真实工作租约，inode永不替换。
- `state`：恰32字节，以0600临时文件写完、fsync、原子替换并fsync目录。

| state字节偏移 | 内容 |
| --- | --- |
| 0～3 | ASCII `ACG1` |
| 4～19 | 16字节初始化随机incarnation |
| 20～27 | 大端uint64 epoch |
| 28 | ASCII `O`（开放）或`C`（关闭） |
| 29～31 | 三个零字节 |

Python票据使用incarnation的hex和epoch，C使用相同24个原始字节；未知版本、长度、
phase、保留字节、权限或链接异常都拒绝。epoch不回绕。每次维护开始和结束均推进。

`ProcessOperationGate.provision(path)`仅显式初始化一个**不存在的新目录**，要求父
目录已存在；遇到已有或不完整目录不覆盖、不修复。应用启动只打开，不自行初始化。
受控维护者以后可使用模块CLI `python -m ai_cat_controller.core.process_gate --init
/绝对路径/新专用目录`；这不是当前设备的执行指令，不可对旧状态反复运行或删目录
重试。本阶段只在pytest临时目录调用初始化。

## 普通工作、必要子任务与维护

普通工作先短持`admission SH|NB`，读取开放票据，再取得独立打开的`work SH`，最后
释放admission。实际工作结束才关闭work FD。维护持有`admission EX`时新工作立即
拒绝，不先读marker再冒险入门；读到持久`C`即使没有活锁拥有者也不能入门。

HTTP入口在body/auth之前捕获当前跨进程票据；维护后旧请求不能靠新世代重新加入。
嵌套request_scope保留最早的原始owner、epoch和关闭期None票据。同域peer也核对
原始owner状态，不用自己的local epoch换票；纯读遇坏协议仍可进入不可写作用域。
自主决策则在首个状态/资料读取之前持租约，等待后再checkpoint，不把旧资料换成
新票据继续发动作。独立循环的180秒空闲等待不占工作锁。

必需的后台收尾通过受控dup继承已有工作锁，不在关闭期间重新争取准入。dup和父
租约close共用小锁，防止跨线程FD关闭/复用后误复制普通文件。每个普通root独立
open，不能共用一个全局FD后一条请求解掉另一条请求的锁。

仅继承ContextVar不等于已接纳工作。父任务还活跃时，必要子任务须通过显式spawn
同步预留自己的实际租约；父租约结束后才执行的raw asyncio子任务，即使保留旧
上下文且本地epoch没有变化，也不能重新入门。外部进程维护完成同样不能使旧上下文
换取新票据；只有无旧请求载荷的长期监视器才可按既有detached规则清除上下文。

FD默认CLOEXEC，只有已接纳的必要opaque播放器/固定命令显式`pass_fds`继承一份
工作FD。父进程在真实子进程回收后只close其副本，不`LOCK_UN`；否则keeper突然
退出或daemon线程结束时，仍活着的子进程可能在没有租约的情况下继续执行。
这依赖Linux的open-file-description锁语义，见[flock手册](https://man7.org/linux/man-pages/man2/flock.2.html)。
显式继承与默认CLOEXEC的区别见[open手册](https://man7.org/linux/man-pages/man2/open.2.html)。

维护先取得admission EX并持久化关闭/新epoch，再运行必要静默检查和停止、等待本
实例已接纳任务，并以非阻塞轮询取得work EX。绝对截止时间与上阶段独立timer仍生效，
**实际独占开始前必须已取得work EX且未过期**，不能拿到HTTP成功响应便视为动作
已经结束。HTTP取消不丢租约，实际线程/子进程收敛之前不能提前宣布排空。

预算超时不执行危险主体；若quiesce仍在真实清理则保持关闭。实际清理结束后可撤销
本次维护、写开放新epoch；外部旧普通工作仍持自己的SH继续收尾，没有把它们假装
结束。下一次维护仍须等待这些真实锁。维护进程崩溃则留下持久C，即使内核释放EX
也不自动恢复；没有PID猜测、TTL、删marker或覆盖初始化的恢复捷径。

## 原生语音的收敛

新增头文件`native/common/ai_cat_process_gate.h`，由SDK准备脚本复制到对应common
目录；SDK本身没有在本轮构建。C只打开已有目录，不创建或修补协议状态。

语音启动遇正常关闭只park，不启动云/声卡、不反复失败重启；坏配置明确失败。
从park恢复会丢弃旧wake/text/interrupt标记，发送方应等待fresh ready后显式重发，
不重放旧问题。已启动进程在连接等待、主循环、录音读返回后/上传前、PCM回调、
工具派发和最终motor spawn前检查，关闭时停止新效果、丢待播并正常退出旧会话。

共享FD一直保留到**进程真正退出**，不在清理前关闭。工具线程创建前同步登记实际
工作计数；创建失败及最终发送结束才递减。退出先关工具准入、等待真实工具收尾，
再join播放线程、停止/销毁SDK和释放音频资源，不能拿`tool_capture_guard=false`
代替完成证明。阻塞的PA、SDK或waitpid未结束时租约仍在，维护只能失败/等待。

## 本轮本地实现：唤醒与直接适配器

以下源码及宿主回归已完成；没有SDK/RISC-V真实构建、设备部署或实机验收。
它们不能计入已部署的全参与者能力。

原生唤醒不仅是等待口令的识别循环。同一SH租约应覆盖真实PA捕获窗口、VAD/ASR
与状态决策，以及本轮口令引发的systemctl启动、提示音实际write/drain/free、
preroll捕获/写入/rename和最终SIGUSR1。阻塞read/recognize返回后及每个新效果前
复核原票据；遇C或epoch变化，先关真实PA、丢弃旧samples和续词prefix，再释放
租约并park。暂停/收敛期间park不持SH，恢复只使用新采集，不换新票据重放旧口令。
维护期间不重新开麦识别停止词；SIGUSR2打断函数仍可独立作为安全旁路，但不能用
它启动云服务、播音或恢复普通写入。

直接构造LocalK1Adapter时，配置了协议的普通设置、服务启动、对话及动作入口仍须
持完整租约，而不能仅依赖外层FastAPI装饰器。服务层已经接纳的必要调用应复用真实
工作租约，不能在关闭期间重新争取准入而卡住必需收尾；独立调用则正常捕获和校验
自己的票据。适配器与服务门的关联不能只比较Path字符串：必须核对实际协调目录、
两把锁的固定身份和incarnation，并保持旧请求scope中的世代。不能通过重新进入
request scope、重新snapshot或创建另一对象，把过期请求刷新成新请求。
仅继承ContextVar也不等于admission：父操作已结束的旧lease不能再申请工作、
checkpoint或维护，即使外部维护没有推进本实例本地epoch。必需后台任务必须在
父租约仍活跃时通过spawn同步预留。

服务注入的维护门只借用；未注入但显式配置协议路径时，首个普通写调用才打开已有
私有协调目录并创建自己的门，不provision或修复。跨度包括音量两步写、wake的
ensure→signal、文字/播音的ensure→request文件线程→signal及失败清理，以及固定
电机/预设命令。关闭适配器只shutdown自己拥有的门，等实际任务收尾后再关闭自己
的coordinator，不关闭服务借用的门；adapter还独立登记实际任务，防止自有门为空
但文字线程实际借外门工作时close提前关coordinator。未配置协议保留兼容行为，
不能据此自报就绪。普通服务的本地播音也继承原SH及opaque工作FD，旧无租约上下文
或独占维护上下文不能退回legacy播放。

失败/撤销唤醒会在原租约内尽力清理本轮已发布handoff。已观察到新inode或内容版本
则不删；身份检查与unlink之间不是原子操作，不解决普通多生产者仲裁。活跃退出
时最后由窗口RAII在模型析构后释放SH，宿主桩验证了阻塞析构不会提前获得EX。
SIGINT/SIGTERM也是普通效果的独立关闭条件：即使协议仍为O，阻塞read/ASR返回后
也不能新启动服务、提示音、预录发布或SIGUSR1；必需清理与SIGUSR2旁路仍可执行。
退出路径不以discardWindow提前释放活跃SH，仍等模型实际析构完成。
初始化期间的退出也不再落入正常 idle release：模型初始化返回后检查退出标志，
VAD 初始化后段退出先销毁 VAD，再由 RAII 先析构模型、后释放原 SH。宿主测试
在两种实际阻塞初始化点发 SIGTERM，并阻塞模型析构；析构结束前 EX 必须失败。
正常初始化后的空闲释放保持不变，不将常驻但空闲的模型当作持续工作租约。

协议关闭、票据过期或对端目录/锁身份发生变化时，普通调用拒绝且不自动重试。
独立停止/打断可以执行，但任何业务回执或运行文件保存仍须走相应正常保护，不能
在维护后补写旧成功记录。没有配置协议的独立脚本与手工命令仍不因此获得保护。

## 全参与者验收合同：已知受管集合，不是全设备证明

本节是待实现、待设备验收的合同，不是新增ready开关、静态JSON认证或已开放的
接口。当前仅有协作锁；配置同一路径或取得work EX不能证明没有旧二进制、漏配置
进程、未知写者或仍在运动的物理机构。

受控发布应固定一份受信清单，约定角色、允许数量、独立/进程内autonomy的唯一部署
模式、协议版本、运行制品和项目代码清单SHA。清单由受控发布链决定，调用方不能
随请求提供“期望”角色、PID、SHA、unit或清单路径。静态清单只规定核验目标，不
作为活性证据；修改清单、代码或启动配置也必须属于受控发布，不能与维护并发替换。

现已新增可独立使用的[离线Python源码候选包](offline-release-candidate.md)构建、
外部SHA核验与只读原子stage。它只证明固定源码/资产字节，不含依赖或原生制品，
后续的[内存导入检查](verified-python-import.md)补上固定角色实际导入的项目源码
字节身份，但不启动服务，也不证明依赖、运行期资源、进程身份或活性。因此仍未
完成受控运行，不替代这里的发布链和活握手要求。

常驻controller、wake、dialog及清单要求的独立autonomy，必须完成本次新nonce的
私有Unix socket活握手。核验器将响应绑定到内核peer PID/UID、进程starttime、
受管unit/cgroup和实际运行制品，而不是信任响应中的自报身份。peer凭据的连接时点
语义见[Unix socket手册](https://man7.org/linux/man-pages/man7/unix.7.html)；不能把
另一个进程继承的监听socket直接当作当前响应者证明。pidfd用于绑定被核验的活进程
并观察退出，不能用PID文件、TTL或最近一次成功应答替代当前活性，见
[pidfd手册](https://man7.org/linux/man-pages/man2/pidfd_open.2.html)。

握手必须由实际已打开协调对象的代码返回，并核对协议版本、incarnation/epoch、
协调目录dev/ino及admission/work两把锁各自的dev/ino；同名路径、ENV字符串或
自报`enabled=true`均不足。进程缺失、旧版不应答、漏配置、角色重复、未知受管子
进程、映像不符、错路径/错inode、过期nonce或核验超时，都只能得到未验证结果。
核验不读取`/proc/PID/environ`或云端密钥，不把私有配置与原始进程资料输出到前端。

原生制品应核验实际运行映像，而非仅哈希磁盘上同名的新文件。Python尤其不能仅
校验解释器：`/proc/PID/exe`指向被执行的映像，不证明已加载的项目源码，见
[proc_pid_exe手册](https://man7.org/linux/man-pages/man5/proc_pid_exe.5.html)。须采用
不可原地修改的版本化发布树/zipapp等受控制品，绑定完整项目代码清单、启动模式与
进程身份；没有这样的发布链时，不能宣告Python角色已通过全参与者核验。

motor CLI和播放器是瞬时后代，不应要求它们空闲时仍常驻。应核验固定受管launcher、
允许制品及当时实际活跃的子进程，并证明它们保留传入的工作FD直到真实结束。
目标paplay/pactl等opaque二进制仍须实测：启动后是否关闭继承FD、keeper异常退出
时是否继续受锁约束、超时回收是否等到真实退出。宿主替身通过不等于目标二进制
通过；仅有自报FD编号或一个存活PID同样不够。

核验结果只能形成短命的known-cohort票据，绑定受信发布清单、进程身份、目录/锁
固定身份及本次世代。维护准入前核验，取得work EX之后、危险主体开始之前再次核验；
此时还须满足绝对截止时间。quiesce造成已验证进程退出/重启时，必须确认旧进程
真实结束，并重新核验同一发布清单的新parked进程，不能继续使用旧PID的证据。
受管启动器必须在关闭期阻止旧版或漏配置实例启动普通工作，不能在核验后留出
systemd重启为legacy进程的窗口。成员、映像、配置或固定身份变化即撤销票据，
不自动换新世代继续清理；独立停止/打断仍保留。

上述证据最多支持“已知受管参与者已验证”。要声称整个设备没有其它写者，还需要
受控启动/设备访问边界、完整厂商服务清单和独立实机验收；未知root脚本、未纳管
服务及驱动退出后的物理停机不由握手证明。因此本轮不实现容易被误读为全设备
ready的静态/synthetic verifier，也不据此开放危险操作或完成整个产品上线goal。

## 明确未完成的范围

- 原生唤醒和直接适配器仅完成本地源码回归；即使源码测试通过，旧二进制
  或未配置同一路径的进程仍可能忽略协议，不能把计划中行为称为已部署保护。
- 原生SDK/RISC-V全链接、真实云端/PA销毁语义与K1延时、硬件实际停机尚未验收。
