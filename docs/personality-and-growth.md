# 性格与培养配置

## 五种性格

| ID | 性格 | 对话风格 | 音色来源 | `voice_type` 标记 | 语音动作白名单 |
|---|---|---|---|---|---|
| `sunny_explorer` | 元气探险家 | 明快、有活力、邀请探索 | 火山控制台当前音色 | `volcengine_console` | 摇头、点头、摇尾 |
| `gentle_companion` | 温柔陪伴者 | 柔和、慢节奏、先倾听 | 火山控制台当前音色 | `volcengine_console` | 点头 |
| `proud_star` | 傲娇小明星 | 俏皮、嘴硬心软、不贬低用户 | 火山控制台当前音色 | `volcengine_console` | 摇头、点头 |
| `curious_scholar` | 好奇小博士 | 清晰解释、鼓励验证 | 火山控制台当前音色 | `volcengine_console` | 点头、摇头、摇尾 |
| `calm_guardian` | 沉稳守护者 | 稳重直接、优先安全 | 火山控制台当前音色 | `volcengine_console` | 点头 |

完整提示词、等级称呼、动作触发规则和禁止内容位于
`src/ai_cat_controller/domain/personalities.py`。首次创建宠物实例时随机选择性格；
重新绑定只恢复原性格，不重新抽取。

Local K1 复用一个火山智能体，在当前 WebSocket 会话中动态更新性格配置。音色不
属于性格配置，全部由火山引擎控制台统一管理：

1. FastAPI 根据设备序列号找到已绑定宠物，并组合性格、人名、亲密度称呼、禁止
   内容和可用动作。
2. 配置原子写入
   `/var/lib/ai-cat-controller/personality-runtime.json`，权限为 `0600`。
3. 原生对话进程只在没有唤醒、收音、思考、播放或工具执行时读取新 revision，
   通过火山 `session.update` 只更新 `LLMConfig.SystemMessages`，不会发送
   `TTSConfig` 或覆盖 `voice_type`。
4. 原生 Function Calling 在执行电机前再次检查性格动作白名单；不允许的动作只
   返回拒绝结果，不启动电机。
5. `toy_motor.service` 从 `/api/v1/personality/runtime` 读取同一性格的安全头部
   动作权重与固定主动短语。K1 使用预生成 WAV 本地播放，每 3 分钟最多 1 句，
   不启动火山服务；播放期间通过 `/run/ai-cat/local-speech-active` 暂停唤醒收音。
   15 个主动短语 WAV 使用控制台当前音色一次性缓存，头部动作结束 2.2 秒后再
   播放。控制台更换音色后必须重新生成这些离线资源。

运行时的 `voice_type=volcengine_console` 和 `voice_source=volcengine_console`
仅表示音色归控制台管理，不是火山实际发音人 ID。

绑定、宠物改名、亲密度跨级和 FastAPI 重启都会刷新配置。设备重启后 SQLite 与
运行时文件会恢复当前性格。`GET /api/v1/personality/runtime` 中
`native_applied=true` 表示原生状态上报的 revision 与 FastAPI 配置一致。

摇尾还受两层限制：亲密度至少 1 级，并且维修验收后显式设置
`AI_CAT_ENABLE_TAIL_MOTION=true`；否则不会出现在语音动作白名单中。

## 长期成长人格 V1

长期成长由 `AI_CAT_ENABLE_GROWTH_PERSONALITY_V1` 总开关控制，默认关闭。关闭时
成长 API 仍可只读已有属性和标签，但不会记录新的成长事件、运行 Debug 养成或把
成长指令写入 `personality-runtime.json`。基础性格、亲密度、动作、语音和对话
历史不受影响。

长期成长人格与已有概念严格分离：初始性格是出生人格，亲密度是当前主人与猫的
关系深度，成长属性记录长期经历，成长标签是稳定的发展结果。最终行为画像为：

```text
BasePersonality + IntimacyLevel + GrowthAttributes + GrowthTags
```

### 属性、事件与偏置

属性包括 `curiosity`（好奇）、`empathy`（共情）、`knowledge`（求知）、
`energy`（活力）、`mischief`（淘气）、`discipline`（自律）。数据库使用
`0..10000` 整数保存百分之一点，对外显示为 `0.0..100.0`，避免浮点累计误差。

| 成长事件 | 基础属性变化 |
|---|---|
| `knowledge_discussion` | 好奇 +1.00，求知 +1.40 |
| `question` | 好奇 +1.00 |
| `emotional_sharing` | 共情 +1.30 |
| `joke` | 淘气 +1.10，活力 +0.70 |
| `casual_chat` | 活力 +0.10 |
| `planning` | 自律 +1.30，求知 +0.30 |
| `encouragement` | 共情 +1.00，自律 +0.70 |
| `physical_touch` | 按头、背、鼻、左右脚配置少量共情/活力/淘气 |
| `completed_task` | 自律 +1.40，求知 +0.20 |
| `daily_meeting` | 活力 +0.40，共情 +0.20 |

最终变化为“基础值 × 性格偏置 × engagement × novelty × repetition decay”。
性格偏置统一定义于 `domain/growth.py`，范围 `0.8..1.3`：元气探险家偏好奇/活力，
温柔陪伴者偏共情/自律，傲娇小明星偏淘气/活力，好奇小博士偏好奇/求知，沉稳
守护者偏自律/共情。连续相同事件和相同话题按 `100%、85%、70%、55%、40%`
衰减；每个真实来源 ID 只能成长一次。

对话分类 V1 使用可替换的本地确定性 `InteractionClassifier`，只输出固定事件枚举、
固定安全话题、固定情绪枚举和 `0..1` 参与度。解析或分类失败回退到
`casual_chat`，不会阻断 ASR、LLM、TTS 或对话历史。实体触摸、任务和每日见面是
确定事件，不调用语义分类器。

### 标签规则

标签必须同时满足属性阈值和累计事件证据，规则集中配置，不在服务中散落判断：

| 标签 | 触发条件 | 进阶关系 |
|---|---|---|
| 小小探索者 | 好奇 ≥55；问题/知识讨论 ≥25 | 可升级为探索家 |
| 探索家 | 好奇 ≥72；问题/知识讨论 ≥60 | 替换小小探索者为 active |
| 小学者 | 求知 ≥55；知识讨论 ≥25 | 可升级为学霸猫 |
| 学霸猫 | 求知 ≥75；知识讨论 ≥60 | 替换小学者为 active |
| 贴心伙伴 | 共情 ≥65；情绪分享/鼓励 ≥35 | 无 |
| 小调皮 | 淘气 ≥60；玩笑 ≥35 | 无 |
| 自律搭子 | 自律 ≥65；计划/任务 ≥30 | 无 |
| 嘴硬心软 | 傲娇小明星；共情 ≥60；亲密度 ≥Lv.2；情绪分享/鼓励 ≥25 | 无 |

被高级标签替换的低级标签保留获得时间、替换时间、触发事件和证据，但不再作为
当前 active 标签进入 Prompt。获得标签同时写入一条 `tag_awarded` 成长事件。

### 数据、运行时与页面

SQLite 在原数据库内按 `pet_id` 新增：

- `growth_attributes`：6 个属性当前固定点值；
- `growth_events`：来源、分类、衰减因子、属性变化和原因元数据；
- `growth_tags`：active/replaced 状态、获得/替换时间、触发事件和证据。

解绑不会重置成长。新主人继承这只猫已形成的属性和标签，但 API 使用事件中的
`user_id` 隔离旧主人的互动详情。格式化体验数据会先备份再清空上述三张表。

`BehaviorProfileService` 把属性映射为普通、初显、成长中、明显、突出五档。只有
跨档、标签变化或亲密度跨级才改变成长 revision；微小数值变化只写 SQLite，不会
频繁写运行时或触发云端更新。行为指令进入现有 `personality-runtime.json` 的
`growth_revision`、`growth_tags`、`behavior_directives`，并随原有
`session.update` 的系统 Prompt 生效。初始性格始终决定表达方式，成长指令只改变
行为倾向，亲密度继续决定称呼和关系语气。

培养页通过 `GET /api/v1/pets/{pet_id}/growth` 展示成长倾向、active 标签、行为
画像和最近原因。Mock 额外显示精确值和快速养成表单；Local K1 默认拒绝 Debug，
只有开发时显式设置 `AI_CAT_ENABLE_DEBUG_GROWTH=true` 才允许批量模拟。成长标签
不会绕过既有动作白名单、亲密度、硬件开关或统一调度器。升级庆祝是独立的已验收
系统事件，不由成长标签直接触发。

## 亲密度

| 等级 | 分值 | 名称 | 主要解锁 |
|---|---:|---|---|
| 0 | 0-19 | 初次相遇 | 基础对话、基础头部动作 |
| 1 | 20-49 | 逐渐熟悉 | 亲近称呼、基础尾部动作、主动问候 |
| 2 | 50-99 | 亲密伙伴 | 组合动作、情绪陪伴 |
| 3 | 100-179 | 深度羁绊 | 庆祝动作、主动陪伴、专属语气 |
| 4 | 180+ | 灵魂伙伴 | 全部动作、最高亲密称呼、纪念日问候 |

默认每日正向增长上限为 50，可通过
`AI_CAT_INTIMACY_DAILY_CAP` 调整。

设置 `AI_CAT_ENABLE_LEVEL_UP_CELEBRATION=true` 后，任一幂等互动使亲密度跨过
`20`、`50`、`100` 或 `180` 分时，系统会等待当前语音会话和电机动作结束，自动
执行固定 `celebration_combo`。触摸恰好升级时，庆祝优先于普通触摸动作，避免两个
动作争抢电机；动作完成后播放共享本地提示语，不启动火山云端。该内部事件只跳过
产品等级锁，不绕过设备在线、动作能力、尾部开关、固定轨迹、互斥、冷却和超时
保护。重复 `request_id` 不会再次触发庆祝。

| 事件 | 分值 | 每日次数上限 |
|---|---:|---:|
| 每日见面 | +3 | 1 |
| 有效对话 | +2 | 5 |
| 触摸反馈 | +1 | 8 |
| 完成互动任务 | +5 | 2 |
| 忽略主动问候 | -1 | 2 |

每个事件必须携带 `request_id`。重复 ID 返回原结果，不重复计分。Local K1 会从
`toy_main` 日志增量导入头部、背部、左右脚和鼻部的实体触摸，并复用相同的幂等、
每日次数与总增长上限。监控从文件末尾开始，不会在服务重启后重放历史触摸。
厂商触摸服务可能为一次持续接触连续上报多条记录；监控按实体部位使用默认
`1.5` 秒尾随防抖，连续事件会延长静默窗口且只生成一个业务事件，避免一次触摸
重复增加亲密度和成长。该值可通过 `AI_CAT_TOUCH_EVENT_DEBOUNCE_SECONDS` 调整。
现场调试可临时设置 `AI_CAT_DEBUG_UNLIMITED_TOUCH_INTIMACY=true`，仅让 `touch`
事件跳过每日次数和总增长上限；幂等保护以及其他互动规则不变，正式环境必须关闭。
触摸标签按设备序列号选择。`7c2b63fd4a128` 使用厂商正常标签；旧设备
`7c2b63fd4a138` 的输入层交换 `nose`/`head` 和 `back`/`left_foot`，
`right_foot` 保持不变。原始标签记录在 `hardware_sensor`，映射类型记录在
`sensor_mapping`，后续动作、语音和亲密度均使用实体 `sensor`。
实体触摸同时通过统一动作调度器提供反馈：头部/背部使用 `head_nod`，鼻部/左右脚
使用 `head_shake`。对话会话活跃、状态异常、电机繁忙、重复事件或 3 秒冷却期内
跳过动作，但不影响本次亲密度规则处理。触摸语音按部位独立防刷并串行播放，电机
冷却不会再同时丢弃不同部位的语音；触摸不会调用尾部动作。

动作完成后可播放对应部位的固定本地短语。系统共享 5 个控制台当前音色 WAV，
分别用于头部、背部、鼻部、左脚和右脚；播放不启动云端服务，且使用与本地主动
短语相同的播放标记暂停唤醒收音。缓存语音固定输出到已验收的实体 PulseAudio
扬声器，不经过云端会话使用的虚拟回声消除输出。只有动作成功进入调度时才安排
短语，冷却或忙碌状态不会单独播音。

浏览器仍保留触摸调试按钮；“完成任务”目前由网页人工确认。正式小程序阶段应改为
服务端任务状态签名上报，不能信任客户端直接声明任务完成。

## 动作安全

动作库位于 `src/ai_cat_controller/domain/actions.py`。当前包含 7 个动作，
每个动作具有固定编号、性格范围、最低等级、执行器方向、名义角度、速度和持续时间。
Pydantic 在进程启动时校验以下范围：

- 角度 `0..45` 度；
- 速度 `0.1..1.0`；
- 单步持续时间 `100..3000 ms`。

网页和小程序只能提交 `action_id + request_id`，不能覆盖这些参数。上述范围目前只
用于 Mock 合同验证；映射到 K1 真实电机前，仍需逐动作完成机械限位、堵转、温升和
紧急停止验证。
