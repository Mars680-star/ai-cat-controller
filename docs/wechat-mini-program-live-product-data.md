上游目前没有完整的“今日互动次数/今日增长合计”聚合字段，仅有最近30条互动。
因此未知合计标为“未提供”，不是0，也不把有限窗口求和冒充全天。任务是否今日
完成没有可靠聚合时不伪造“已完成”，仍由服务器在提交时检查每日规则。

正式成长事件公开的是变化属性，而不是每条精确增量；页面展示“某属性发生变化”，

置零。真实模式没有成长加速入口，直接调用旧演示方法也不会触发真实调试接口。

## 网关合同

以下路径位于电脑8787，`petId`为当前微信账号的授权编号，不是K1网页产品编号。
请求不能携带设备地址、网页会话、用户编号、元数据或任意指令。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/pets/{petId}/dashboard` | 主页产品数据与最近互动 |
| GET | `/v1/pets/{petId}/intimacy` | 培养数据、规则、记录和写开关 |
| GET | `/v1/pets/{petId}/growth` | 六维成长、标签、画像及成长记录 |
| POST | `/v1/pets/{petId}/interactions` | 一次显式培养互动 |

互动请求只接受：

```json
{"eventType":"daily_check_in","requestId":"interaction-example-001"}
```

`eventType`固定为 `daily_check_in`、`touch`、`completed_task`、`ignored_greeting`。
不能上传 `valid_dialog`、积分、等级、属性增量、次数、调试开关或设备元数据。
请求编号1～64位ASCII字母数字或 `_ . : -`；无查询参数，拒绝多余字段和超大请求体。

资料读取前后及写入边界校验：微信会话、设备归属、登记完整序列号、物理K1身份、
真实网页会话拥有的产品宠物和稳定所有者。失效即拒绝，不自动重新登录、认领设备
或改用低级接口。仅返回有界字段，剥除上游内部用户/设备编号、完整序列号、
鉴权材料、原始元数据、调试证据和同步内部状态。

## 培养写入与未知结果

写接口默认关闭，由服务端 `--enable-interactions` 单独开放，与电机开关独立。
响应的 `interactionsEnabled` 同时反映普通互动规则是否通过校验；若设备启用无限
触摸调试或相关规则未验证，保持可读但关闭培养写入，不修改原设备配置。

确认弹窗提醒真实积分/成长会改变。设备原有升级庆祝配置可能在积分升级时触发
动作；网关不另发庆祝、也不打开尾部或自动动作开关。用户测试前应保持周边安全。

- 意图先写入电脑独立私有账本，再向K1发送；相同用户/宠物/编号返回原回执，不
  重发上游POST，同编号改变互动类型返回冲突。上游编号隔离不同微信用户和宠物。
- 不自动重试。明确查询同编号仍返回既有回执；每日见面由K1本地日期归一化，
  因此跨天也不能把未知请求擅自补发成新一天的签到。
- `recorded`只说明设备产品服务返回了已校验的业务记录；积分可能因规则为0或
  因重复不再增加，不代表伴随的物理庆祝已经完成。
- `unknown`表示可能已提交但未确认。重启遗留的`sending`也转为未知；同一固定
  设备/产品账本有未确认意图时阻止新编号，换页面、换账号或重启不解除。
  没有面向客户端的清锁接口，不得删账本或换编号绕过。
- 页面隐藏、换设备、授权刷新会撤销旧确认和隔离晚到响应；提交后离页不会撤销
  K1已收到的互动，也不把同一用户未来的新请求当作旧回执。
