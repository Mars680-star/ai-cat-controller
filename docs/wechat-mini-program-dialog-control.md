## 功能与操作

在原“对话”页继续使用共享微信登录和已授权设备，保留真实语音状态、已保存
会话摘要及详情。文字提问、开始或继续聆听、打断并结束由独立控制链路提供；
未部署新接口、未开放开关、身份未验证或状态过期时，按钮明确不可用。
不把控制链路故障变成演示成功，也不影响原本独立的只读历史。

同时补齐原生实际存在的 `processing_audio`（问题已发送、等待云端确认）、
`followup_preparing`（播放收尾、准备继续聆听）、`connected`、`stopping` 和三种
`proactive_*` 状态。此前小程序与网关白名单遗漏它们，正常对话途经这些阶段
也会被判成未验证；现在保持真实阶段，
不伪装成已回答或已经可以追问。未知的新状态仍然拒绝，不放开任意状态字符串。

每次控制都需要用户点击并确认。聆听会打开设备的语音输入，文字会进入原实时
云端对话且可能由扬声器回答；原设备已经启用的语音动作规则仍可能生效。本次
不改这些规则、动作参数、音量、云端密钥或声卡配置，也不在小程序手机端录音。
打断仅结束本轮，不擅自开始下一轮；不新增主动 TTS 或其他后台播音入口。

真实草稿与原预览草稿分离；原预览的发送/重试保留。真实正文只在内存中编辑，
不写入小程序持久存储，也不放进查询地址、日志或本地网关账本。输入与上游一致，
最多 500 字符，拒绝空白和控制字符；刷新状态不能清空正在编辑的文字。

确认期间若隐藏页面、切换身份/设备、修改正文或控制条件改变，应取消这次提交，
不会在以后恢复时补发。重新确认是新的一次用户意图，不是自动重试旧请求。

## 固定接口

路径属于电脑 8787 网关，`petId` 是微信账号的授权设备编号，不是网页产品编号。
客户端不能提交服务器地址、用户编号、网页会话、设备密钥或任意上游路径。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/pets/{petId}/dialog/control` | 独立控制开关、当前能力与限制 |
| POST | `/v1/pets/{petId}/dialog/commands` | 一次确认后的固定指令 |
| GET | `/v1/pets/{petId}/dialog/requests/{requestId}` | 只核对原请求回执，不重发 |

命令只允许 `requestId`、`kind` 和仅文字需要的 `content`：

```json
{"requestId":"dialog-example-001","kind":"text","content":"你好，介绍一下自己"}
```

`kind` 固定为 `text`、`listen`、`interrupt`；其他字段和查询参数拒绝。
仅新命令路由获得足够容纳 500 汉字的有界请求体预算，不放大已有登录、动作或
培养接口的限制。服务端严格核对上游回执的请求编号、类型对应状态和布尔值，
不把任意 HTTP 200 或包含原始设备信息的对象直接传给客户端。

控制器只使用三个上游 POST：`/api/v1/dialog/text`、`/api/v1/dialog/wake`、
`/api/v1/dialog/interrupt`。不使用会产生本地模板回答的产品 Mock 对话接口，
也不调用旧的带成长同步副作用的历史 GET 来证明控制能力。

## 权限、重复点击与未知结果

微信会话、设备归属、登记的完整序列号、物理 K1 身份、真实网页授权和稳定的
产品所有者都需要验证，派发前再次检查。新设备接口还必须提供专用
`persisted_dialog_readonly_v1` / `read_only=true` 能力证明；缺少证明不退回旧链路。
只读 Reader 继续只接受 GET，写请求在独立控制器中实现。

- 网关将意图先提交到独立私有 SQLite 账本，再向 K1 派发一次。相同编号和相同
  内容摘要返回原回执，不重复 POST；同编号更换种类或正文返回冲突。
- `accepted` 只说明收到了已校验的服务端接收回执，不能写成回答、播音或动作
  已完成。回答内容仍以原会话记录为准，不在小程序拼出假回答。
- `unknown` 或进程重启遗留的 `sending` 表示可能已经派发。阻止新的文字和聆听，
  保留同编号 GET 核对入口；不清账本、不换编号、不开公共清锁接口。
- `not_sent` 表示该意图在派发前被拒绝，不自动重试；再次发送仍需新的确认。
- 打断使用独立通道，不被前一个文字/聆听未知结果阻塞，但仍验证身份和版本。
  打断接收回执不能证明延迟的原请求不会到达，因此不会清除原来的未知锁。
- 小程序在 POST 前保存有界未决标记，只含用户/设备/编号/命令种类，不含正文或
  凭据。保存失败就不 POST。切页、重编译、重登或切换账号不能抹掉旧未决请求；
  重新打开只核对回执，404 也不能证明一个延迟请求永远不会抵达。
- 所有轮询均是读取；错误后暂停自动重试，隐藏页面立即停轮询并隔离旧响应。
  开页、刷新、选择设备或收到记录都不能自动发送控制指令。
